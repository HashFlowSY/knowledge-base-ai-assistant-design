# Backend Security Guidelines

## Server-Side Authorization

UI gating is not security. Every protected operation must enforce authorization on the server.

Required checks:

- Authenticated user for member operations.
- `admin` role for admin operations.
- Tenant scope for every tenant-owned entity.
- Knowledge-base authorization for documents, chunks, retrieval, upload, and chat.

Retrieval paths must apply tenant and knowledge-base filters before returning or reranking results.

## Tenant Scoping

Every tenant-owned table must include `tenant_id` directly or be reachable through a required tenant-owned parent.

Rules:

- API and package functions that read tenant-owned data must accept `tenantId`.
- Queries must filter by `tenantId` before returning data.
- Cross-tenant joins must be impossible in normal domain helpers.
- Audit logs must include `tenantId` when available.
- Background jobs must include `tenantId` in payloads and persisted job records.

Single-enterprise mode still uses a default tenant. Do not special-case code paths to skip tenant checks.

## Knowledge Base Authorization

Knowledge-base permissions are the main content access boundary.

Rules:

- Documents inherit knowledge-base permissions.
- Chunks inherit document and knowledge-base permissions.
- Retrieval must filter by authorized knowledge-base ids.
- Upload and URL import require write access to the target knowledge base.
- Chat requests must validate selected knowledge-base ids against actor permissions.
- Admins can manage all knowledge bases in the tenant.
- Members can access only assigned knowledge bases.

## Token and Secret Handling

Never store raw bearer tokens, one-time codes, reset tokens, or integration tokens in the database when a hash can be used.

Use a strong random token generator and store only a derived value.

Rules:

- High-entropy random bearer/reset/integration tokens may be stored as a SHA-256 or HMAC-SHA-256 digest.
- Low-entropy user-entered codes must be protected with a server-side secret or a slow password-hash style verifier.
- Compare fixed-length encoded digests, not raw attacker-controlled token strings.
- Store token purpose, expiry, and revocation status with the digest.

Example for a high-entropy random token digest:

```typescript
export async function hashToken(token: string): Promise<string> {
  const encoder = new TextEncoder();
  const data = encoder.encode(token);
  const digest = await crypto.subtle.digest("SHA-256", data);
  return Array.from(new Uint8Array(digest))
    .map((byte) => byte.toString(16).padStart(2, "0"))
    .join("");
}
```

Use timing-safe comparison for fixed-length digest checks.

```typescript
export function timingSafeDigestEqual(aDigest: string, bDigest: string): boolean {
  if (aDigest.length !== bDigest.length) {
    return false;
  }

  let result = 0;
  for (let index = 0; index < aDigest.length; index += 1) {
    result |= aDigest.charCodeAt(index) ^ bDigest.charCodeAt(index);
  }

  return result === 0;
}
```

Provider keys and object storage credentials must be encrypted at rest when persisted and redacted from logs and audit metadata.

## Authentication Middleware

Authentication middleware should:

1. Read session credentials from the supported transport.
2. Validate the session.
3. Attach normalized `session`, `actor`, and `tenantId` context.
4. Add actor context to the request logger.
5. Fail closed for protected routes.

Admin middleware should build on authenticated context and check role explicitly.

## Input Validation

Validate all external input with Zod or an equivalent schema parser before it reaches package logic.

External input includes:

- Request body.
- Query parameters.
- Path parameters.
- File metadata.
- URL ingestion input.
- Provider config.
- Webhook payloads.

## File Upload Validation

File upload routes must enforce:

- Maximum file size.
- MIME type allowlist.
- Extension allowlist as secondary signal.
- Parser support check.
- Object storage key generated by server, not provided by client.

Production v1 supported document types:

- PDF.
- Markdown.
- TXT.
- HTML from URL ingestion.

Unsupported types such as DOCX, XLSX, CSV, and PPTX must fail with a clear validation error until explicitly added to scope.

## SSRF and URL Ingestion

URL ingestion must enforce:

- Protocol allowlist.
- Private IP and localhost blocking.
- Redirect target validation.
- Timeout limits.
- Response size limits.
- Content type checks.

Redirects must be revalidated at every hop. DNS resolution and IP classification must be performed on the final target before fetching content.

## CORS and CSRF

CORS must default to the deployed web origin, not `*`, for authenticated APIs.

CSRF protections must match the Better Auth session transport. State-changing browser-authenticated routes must either use Better Auth's CSRF/session protections or an explicit project CSRF mechanism.

Public health endpoints must not expose sensitive configuration.

## Audit Logs

Audit admin and security-sensitive events:

- Login/session events where applicable.
- Provider config create/update/disable.
- User management.
- Knowledge-base membership changes.
- File upload and URL ingestion.
- Permission changes.
- Failed admin authorization attempts.

Audit logs must not include raw secrets, full prompt text, or full document/chunk content.

## Rate Limits

Apply rate limits to:

- Login and auth routes.
- Upload routes.
- URL ingestion routes.
- Chat routes.
- Provider status/check routes.
- Admin mutation routes.

Rate limit keys should include tenant and actor when authenticated, and IP/user-agent summary when unauthenticated.
